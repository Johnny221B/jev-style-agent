# Jev × AndroidWorld: Compute-aware Agent RL (starter)

**Status: research scaffold, not a trained AndroidWorld agent.** The offline mock tests run; real AndroidWorld action mapping and verl's token-accurate training adapter are intentionally documented as integration tasks. Do **not** claim real RL or AndroidWorld success from smoke-test results.

## Goal
Train a Qwen 4B/8B GUI agent to choose between direct actions and `CALL_JEV`. A fixed Jev API chooses from *existing* UI actions or returns to the LLM based on its confidence and an independent escalation decision. Jev may control up to `max_jev_steps_per_handoff` consecutive environment actions. Reward is task success minus measured decision cost. Jev tokens must be **masked** in verl optimization.

## Quick start (CPU, no API, no emulator)
```bash
conda create -n jev-agent python=3.11 -y
conda activate jev-agent
pip install -e '.[dev]'
bash scripts/smoke.sh
```
This tests only control logic with mocked LLM/Jev and a fake three-click UI.

## Real-model inference smoke test
Set `OPENAI_BASE_URL`, `MODEL_NAME`, `JEV_API_KEY` in your shell (see `.env.example`; do not commit credentials). Start a **local** OpenAI-compatible vLLM server, then:
```bash
python -m jev_agent.cli --controller hybrid
```
The CLI still uses the mock environment. Use this to test response formatting and Jev API behavior, not AndroidWorld quality.

## Research plan
1. **P0:** Set up an Android SDK emulator with AndroidWorld, verify `minimal_task_runner.py` and automatic evaluation (docs/ANDROIDWORLD.md).
2. **P1:** Build `AndroidWorldEnvironment` adapter from `env_launcher`, task registry, accessibility tree, and native `AndroidAction`. Record action type + parameters; validate via `task.is_successful(env)`.
3. **P2:** Implement candidate proposal for clicks based on UI elements; free-form typing is generated by LLM, not Jev. Enforce max candidates, no-progress detection, and no high-risk irreversible actions in pilot.
4. **P3:** Run pure LLM, pure Jev, and fixed hybrid inference baselines; measure success, latency, calls, GPU utilization, Jev confidence calibration.
5. **P4:** Integrate token-accurate multi-turn rollouts into a **pinned** verl version. Use verl's `LLMServerClient.generate()` returning token IDs. Preserve full input/output token IDs, set `response_mask=0` for Jev/tool/environment tokens, never reconstruct via chat API.
6. **P5:** First 4B LoRA GRPO then 8B; compare task reward and cost-penalized reward, SFT/no-SFT ablations, random and confidence delegation.
7. **P6:** Hold out task templates and parameter seeds; evaluate fixed-budget performance; report both trained Qwen-alone and trained Qwen+Jev.

## Important caveats
- Jev's confidence is *not* empirically calibrated for AndroidWorld. Fit thresholds **only on training/validation states**.
- Jev can only choose from a preconstructed candidate set. Candidate generation must not covertly use an expensive LLM every step.
- API calls, emulator IO, and weight-update GPU-hours all count. Use equal total budgets.
- No teacher labels / LLM critic needed for the initial terminal environment reward protocol; sparse reward may limit learning.
- verl Agent Loop APIs are evolving; server agent must adapt to the checked-out version before running GRPO.

See `docs/ANDROIDWORLD.md`, `docs/VERL_INTEGRATION.md`, `docs/EXPERIMENTS.md`.

## AndroidWorld adapter (added in v0.2)

`src/jev_agent/androidworld_env.py` connects to **the official installed AndroidWorld SDK**, using its `env_launcher.load_and_setup_env`, `TaskRegistry`, task initialization and `is_successful` evaluation. It reads `env.get_state().ui_elements`, preserves element indices, and executes `json_action.JSONAction` using the upstream `execute_action` method. First-version candidate actions: click visible clickable/checkable elements, back, scroll up/down. **Free-form text entry and screenshot-grounding are not yet supported.**

Install upstream separately (do not vendor it):

```bash
bash scripts/check_android_host.sh
# Set up Pixel 6 / API 33 AVD, launch separately with -grpc 8554
# Follow https://github.com/google-research/android_world#installation
python -m jev_agent.androidworld_cli --task ContactsAddContact --controller hybrid --mock-models
# For real model tests: configure local Qwen endpoint and JEV_API_KEY in environment;
# don't paste keys in code or GitHub.
python -m jev_agent.androidworld_cli --task ContactsAddContact --controller hybrid
```

**Integration caveat:** the official AndroidWorld code may change. The adapter follows the current official task lifecycle and T3A `JSONAction` interface, but it has not been exercised against a running emulator in this environment. Server-side agent should verify action strings (`navigate_back`, `scroll`) and UI element properties against its pinned checkout before running paid calls. GRPO in verl is a documented next phase, **not yet integrated**.
